VCamdroid：把旧 Android 手机变成 Windows 摄像头

用户结果

在 Android 手机上采集并编码视频，再通过 USB/ADB 或同一局域网传给 Windows 客户端，注册为可被视频应用识别的虚拟摄像头。

E0 · 待验证了解证据与评分 ↗

项目概述

复用闲置 Android 手机的摄像头，作为 Windows 10/11 的视频输入。

适用设备

  • 上游前提列出 Android 7.0 或更高版本的手机，以及 Windows 10 或 11 电脑。
  • USB 路线需要可用数据线、ADB 与手机端 USB 调试授权；Wi-Fi 路线要求手机和电脑位于可互通的同一网络。
  • 具体手机的 Camera2、硬件编码、分辨率和稳定性仍需逐机验证。

适合谁

  • 手里已有 Android 7+ 备用机和可管理的 Windows 10/11 电脑。
  • 愿意先用 USB 路线验证，再决定是否开放 Wi-Fi 路线。

先别选，如果

  • 需要 macOS/Linux 摄像头方案、不能取得 Windows 管理员权限，或不能接受 USB 调试。
  • 需要已证明的跨设备低延迟、音频或长期稳定性保证。

动手前

  • Windows 端需要管理员权限运行 install.bat，以注册 Softcam DirectShow 过滤器。
  • 手机端需要安装 APK；USB 路线还要启用开发者选项和 USB 调试。
  • Wi-Fi 路线可能需要放行 Windows 防火墙；应先确认网络隔离与隐私边界。

停止条件

  • 不能确认电脑是受支持的 Windows 版本，或无法接受安装并注册第三方虚拟摄像头驱动时停止。
  • ADB 设备始终不可见、手机不支持所需编码路径，或 Wi-Fi 被 AP isolation / 防火墙阻断时先排障，不把失败解释为已兼容。
  • 上游 README 没有给出完整卸载/回滚流程；在无法确认驱动移除办法的电脑上不要继续安装。

风险与恢复

主要风险

  • USB 调试会授予已确认电脑 ADB 权限；只在自己控制的电脑上授权，并在结束后撤销不再需要的授权。
  • Wi-Fi 视频流和防火墙放行会扩大本机网络暴露面；不要在不可信网络上默认开放。
  • 性能、延迟、音频、耗电和长期稳定性没有经过 KitAgain 实机测试。

回退边界

  • 优先在非主力电脑和备用手机上试用，并先记录 Windows 端注册的组件与手机端权限。
  • 出现问题时先停止客户端、断开 ADB/网络连接并撤销手机授权；驱动移除必须以当前上游说明或 Windows 组件记录为准。
