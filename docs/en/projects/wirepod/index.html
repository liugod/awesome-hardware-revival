What changes for this device

Before

Some Vector voice capabilities depend on external services whose availability affects continued use.

After

A self-run wire-pod service receives and processes voice requests, with optional knowledge services.

This moves service dependencies to a host you maintain. It cannot repair the robot's battery, display or network hardware. Follow current official setup instructions for Vector 1.0/2.0; server certificates, networking and device configuration all need acceptance checks. Cloud models versus other backends affect privacy, cost and offline capability. A self-hosted service does not automatically make the whole pipeline offline.

A good fit for

People with a working Vector who can run and maintain LAN services over time.

Not a good fit for

People whose robot cannot power on or who do not want to maintain an always-on host.

Proposed reproduction checks

  • Record the device version and check server-to-robot networking.
  • Verify local voice commands and optional knowledge questions.
  • Retest after rebooting server and robot, recording external-network dependencies.

These hardware checks have not been performed by this catalog.
