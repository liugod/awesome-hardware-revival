HK1 Box：先外置启动，再决定是否写入 Armbian

用户结果

把上游支持表中的 HK1 Box 作为 S905X3 电视盒路线核对，先从 USB/TF 启动并验证设备树、网络、存储和散热，再决定是否写入 eMMC。

E1了解证据与评分 ↗

项目概述

在准确板型匹配时，把闲置电视盒作为 Debian/Ubuntu 兼容的小服务器。

本页公开资料核查 2026-11-07

★ 3/5值得比较
  • 4/5 个维度有可核验来源
  • 仅用有可核验来源的维度计算；未取证维度保留为 null，不用中性分补位。

适用设备

  • ophub 支持表列出的 HK1 Box / Amlogic S905X3 路线。
  • 需要逐机核对主板、内存、网卡、存储和 meson-sm1-hk1box-vontar-x3 设备树；同名外壳不能证明一致。
  • 特定 issue 涉及亚克力风扇版的 LED 与风扇 GPIO，不能外推到所有 HK1 Box。

适合谁

  • 手里已有可识别为 S905X3 路线的 HK1 Box，并愿意先做非破坏性外置启动。
  • 需要 Docker、文件服务、Home Assistant 或轻量网络服务，并能维护 Linux 主机。

先别选，如果

  • 同名盒子但板型/网卡/存储未知，或没有原厂备份。
  • 需要即插即用媒体认证、已证明性能或零维护设备。

动手前

  • 保存原厂 Android 镜像和启动分区，并准备与准确硬件相符的恢复资料。
  • 先用 USB 或 TF 卡启动，分别验证启动、网络、存储、显示、重启和温度。
  • 明确要运行的服务、供电和散热条件；不要仅因能启动就直接写 eMMC。

停止条件

  • SoC、主板丝印、网卡/存储芯片或设备树无法匹配时停止。
  • 外置启动不稳定、网络或存储缺失、风扇不转或温度异常时停止。
  • 没有原厂备份、恢复镜像或可执行救砖路径时，不写入 eMMC。

风险与恢复

主要风险

  • 错误设备树可能导致无显示、无网、存储不可见或无法启动。
  • 写入 eMMC 会替换原系统，失败可能需要恢复分区或刷回原厂镜像。
  • KitAgain 未实测功耗、性能、DRM、散热或长期稳定性。

回退边界

  • 把外置介质启动作为第一道回退；在外置启动未稳定前保持 eMMC 不变。
  • 若已写入 eMMC，只使用与准确板型匹配的上游备份/恢复资料；无法确认时停止继续写入。
