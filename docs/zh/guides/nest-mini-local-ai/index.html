NEST MINI · LOCAL AI

Nest Mini 改本地 AI：Onju 换板、HA 卫星还是停手

第二代 Nest Mini 可以通过 Onju ESP32-S3 替换板变成本地 AI 语音端点；这不是刷写 Google 原厂固件，也不是在音箱芯片上运行大模型。

先说结论

能，但现实路线是换板

第二代 Google Nest Mini 可以复用外壳、麦克风、喇叭、触控和静音开关，变成本地或可选云端的语音端点。Onju 路线装入 ESP32-S3 替换板，音频经网络送到外部 ASR → LLM → TTS 管道，或接入 Home Assistant Assist。它既不是原厂固件越狱，也不是在音箱芯片上跑大模型。

先纠正两个常见误称

“jailbreak Google Nest Mini”通常说的是换板

Onju v2 仓库简介使用了 jailbreak，但其硬件方案是第二代 Nest Mini 的替换 PCB：Google 原主板会被拆下。因此原厂 Google Assistant、Cast 与原有多房间链路也随之失去；保留原主板才是现实的物理回退。本页没有证据证明存在面向 Google 原厂固件的纯软件越狱。

LLM 不在音箱里运行

ESP32-S3 负责采集和播放音频、处理触控，并通过 Wi-Fi 传输音频。语音识别、对话和语音合成运行在另一台主机或服务上。Onju v2 记录了 Ollama 等 OpenAI 兼容后端，也可使用可选云 API。这里的“本地 AI”可以是局域网主机上的管道，不是把 7B 模型塞进音箱板。

三条路线怎么选

路线保留什么失去 / 需要什么适合谁停手信号
A. Onju v2 对话或 Agent 管道Nest Mini 2 外壳、麦克风、喇叭、触控；可选本地或云端兼容 LLM 后端。失去原主板、Google Assistant、Cast 与保修；需要替换板、拆机、Wi-Fi 和常开 ASR/LLM/TTS 主机。想要可折腾的对话端点，并愿意维护服务端管道。必须保留 Cast/多房间、只想要成品，或不愿常开主机。
B. Onju 板 → ESPHome → HA Assist同样复用实体硬件，由 HA 管理唤醒词、Assist、媒体/TTS、LED 与触控。同样要换板；需要可用的 HA 语音管道。共享 I2S 使播放时暂停监听。已经运行 Home Assistant，更想要语音卫星而非独立 Agent 客户端。不用 HA、必须边听边播，或不能接受管道调试。
C. 停手保住完整 Nest Mini，或节省时间改买受支持端点。没有改造成果；可改买 HA Voice PE、另做 Wyoming/ESP 卫星，或继续原厂。更在意可靠控制与支持，而不是复用外壳。代际不明、排线/接口损坏、供电不明、无回退，或时间与配件超过价值。

硬件与代际边界

本决策页只覆盖 Onju 资料明确描述的第二代 Nest Mini 外形与硬件路线，不声称支持第一代 Google Home Mini、其他 Google Home 产品或外观相近修订。购买前核对准确型号和板卡文档。若在意回退，断电拆机、记录排线走向，并给原主板和螺丝分组留存。

换板后它就是一套新系统。麦克风隐私、静音行为、Wi-Fi 凭据、固件更新和暴露的服务端口都要重新负责，不能继承原产品的安全假设。

Onju v1 与 v2 怎么摆

原 Onju Voice 仓库已明确标记 deprecated，并指向 Onju v2。v1 README 说明它是实验性对话平台、需要外部服务器，也不是完整 Home Assistant 替代。把它当历史和换板概念证据，不要当默认现行软件路线。

本页把 v2 作为当前上游路线。它把 ESP32 端点与服务器管道分开，并记录对话式与 agentic 后端。旧版 demo 不能证明 v2 的每项功能，仓库文档也不等于 KitAgain 已实机复现。

接本地 LLM 时实际在搭什么

  1. 端点：Onju ESP32-S3 板采集麦克风音频，并通过复用喇叭播放返回音频。
  2. 网络：音频在端点与主机之间传输；网络故障也会变成语音故障。
  3. ASR：Whisper 兼容或上游记录的识别服务把语音转成文字。
  4. LLM / Agent：Ollama 等 OpenAI 兼容端点可运行在合适的局域网主机，也可选择远程 API。
  5. TTS：本地或远程语音服务生成回复音频。

需要一台性能适配所选模型的常开主机。KitAgain 没有测量这套改造的延迟、音质、功耗或最低主机规格，因此不作性能承诺。

什么时候 Home Assistant 路线更合适

如果目标是“控制家居，并使用已有 Assist 管道”，ESPHome 卫星更容易理解。原生 ESPHome 固件和较早的 卫星配置针对的是 Onju PCB，不是 Google 原主板；前提是已经装好替换板并配置 HA 语音管道。

共享 I2S 总线是重要限制：麦克风监听与喇叭播放不能同时进行，播放时唤醒词检测暂停，结束后恢复。如果必须随时打断或连续监听，买配件前就应停手，对比专用硬件。

会失去什么，以及何时停手

  • 原厂服务：换掉原板后，应视为失去 Google Assistant、Cast 与原厂多房间行为。
  • 保修与物理风险：拆壳换电子件可能损坏排线、塑料、麦克风或喇叭。
  • 成品简洁性：固件、Wi-Fi、语音管道、模型服务与恢复都由你维护。
  • 音频并发：ESPHome 路线明确记录共享 I2S 的听放限制。
  • 成本未知：制板、运费、工具、主机、电费与可选 API 因人而异。成本线索见 Onju v2 项目记录；本页不编造总价。

无法确认设备代际、装回前无法访问首次刷写接口、没有安全拆机/供电方案、必须保留 Cast，或只想要受支持成品时，就应停手。Home Assistant Voice Preview Edition 是直接“买而不改”的对照；Wyoming 或 ESP 卫星也能避免牺牲 Nest。

FAQ

Nest Mini 能摆脱 Google 云做本地 AI 吗？

第二代可以通过 Onju ESP32-S3 换板成为端点，并在家庭服务器运行 ASR、LLM 与 TTS。它是硬件替换，不是解锁 Google 原厂固件。

Onju 会刷写 Nest Mini 原主板吗？

不会。文档路线是装入定制 PCB。想保留物理回退，就保存好原主板。

ESP32-S3 能跑大语言模型吗？

在这套架构里不能。它负责音频和控制；模型在 Mac、PC、服务器或可选云 API 上运行。

该选 Onju v2 还是 ESPHome？

想用对话/Agent 服务器管道选 Onju v2；想把设备作为 Home Assistant Assist 卫星选 ESPHome。两条都需要替换板。

什么时候直接买 HA Voice PE？

想要受支持硬件、不愿拆 Nest Mini、希望更快接入 HA 语音，或不能接受音频与维护取舍时，直接购买更合适。
