VCamdroid: turn an old Android phone into a Windows webcam

USER OUTCOME

Capture and encode video on an Android phone, send it to a Windows client over USB/ADB or the same local network, and expose it as a virtual webcam to video applications.

Reuse a spare Android phone camera as a video input for Windows 10 or 11.

Applicable devices

  • The upstream prerequisites name phones on Android 7.0 or later and PCs on Windows 10 or 11.
  • USB needs a data cable, ADB, and phone-side USB-debugging authorization; Wi-Fi needs a mutually reachable local network.
  • Camera2 behavior, hardware encoding, resolution, and stability still require per-phone verification.

A good fit if

  • You already own a spare Android 7+ phone and administer a Windows 10/11 PC.
  • You can validate USB first before deciding whether to enable Wi-Fi.

Skip this route if

  • You need a macOS/Linux route, lack Windows administrator rights, or cannot accept USB debugging.
  • You need proven cross-device latency, audio, or long-term reliability guarantees.

Before you start

  • The Windows install.bat needs administrator rights to register the Softcam DirectShow filter.
  • The APK must be installed on the phone; the USB route also requires Developer Options and USB debugging.
  • The Wi-Fi route may need a Windows Firewall rule; check network isolation and privacy boundaries first.

STOP CONDITIONS

  • Stop if the PC is not on a stated Windows version or if installing and registering a third-party virtual-camera filter is unacceptable.
  • If ADB never sees the device, the phone lacks the required encoding path, or AP isolation/firewall blocks Wi-Fi, troubleshoot first; do not convert failure into a compatibility claim.
  • The reviewed README does not document a complete uninstall/rollback procedure. Do not install on a PC where the filter-removal path cannot be established.

Risk and recovery

Key risks

  • USB debugging grants ADB access to an approved computer. Authorize only a computer you control and revoke access when it is no longer needed.
  • A Wi-Fi video stream and firewall allowance increase local-network exposure; do not leave them open by default on an untrusted network.
  • KitAgain has not tested performance, latency, audio, battery use, or long-term stability.

Recovery boundary

  • Prefer a non-primary PC and spare phone, recording the registered Windows component and phone permissions before the trial.
  • On failure, stop the clients, disconnect ADB/network access, and revoke phone authorization. Remove the filter only using current upstream instructions or verified Windows component records.
