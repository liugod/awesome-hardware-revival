How this changes the device

What was holding it back

An old router's vendor firmware may lack desired features or no longer receive updates.

What it can do afterwards

OpenWrt on an exactly supported hardware revision can provide routing, access-point or other networking roles.

A mature project does not mean a particular old model still supports the current release. Brand, appearance and retail name are insufficient for choosing an image: verify hardware revision, flash and RAM. First-install and upgrade images may differ. Recovery depends on the bootloader, serial access or vendor recovery mode. Do not experiment on the home's only network gateway without a confirmed recovery route.

A good fit if

People with backup networking who can verify device revisions and recovery documentation.

Skip this route if

People with tiny-flash devices, no exact model entry, or no tolerance for temporary network loss.

Checks after the build

  • Check the exact device page, hardware revision, image type and checksum.
  • Back up configuration and device-specific partitions; confirm recovery tools.
  • Test WAN/LAN, wireless and rebooting. One successful connection is not a stability test.

Use this as your acceptance checklist; KitAgain has not completed these hardware tests hands-on.

What can go wrong, and how to get back

Data-loss risk: Expected; Bricking / boot-failure risk: Possible. This is route-based guidance and has not been tested on every device.

Failsafe only applies when the device still boots. A non-booting unit may need model-specific TFTP/UART/programmer recovery. A factory reset is not universal unbricking.
