Nest Mini Local AI: Onju Board Swap vs HA Voice Satellite vs Stop

A second-generation Nest Mini can become a local-AI voice endpoint through an Onju ESP32-S3 replacement board. This is not a flash of Google’s stock firmware, and the speaker does not run a large language model on-chip.

THE SHORT ANSWER

Yes—but the realistic build replaces the board

You can reuse a 2nd-gen Google Nest Mini enclosure, microphones, speaker, touch controls, and mute switch as a local or optionally cloud-connected voice endpoint. The Onju route installs a drop-in ESP32-S3 board. Audio then travels over your network to an external ASR → LLM → TTS pipeline or to Home Assistant Assist. It is neither a stock-firmware jailbreak nor an on-device LLM.

First, correct two common misconceptions

“Jailbreak Google Nest Mini” usually means a board transplant

The Onju v2 repository uses “jailbreak” in its description, but its documented hardware is a replacement PCB for the second-generation Nest Mini. You remove the Google board. That means losing the original Google Assistant and Cast path; retaining the old board is the practical rollback. This guide does not establish a software-only jailbreak for Google’s stock firmware.

The LLM does not run inside the speaker

The ESP32-S3 captures and plays audio, handles controls, and moves compressed audio over Wi-Fi. Speech recognition, conversation, and speech synthesis run on another machine or service. Onju v2 documents OpenAI-compatible backends including Ollama and local Apple-Silicon services, alongside optional cloud APIs. “Local AI” here can mean a LAN-hosted pipeline, not a 7B model squeezed onto the speaker board.

Hardware and generation boundary

This decision guide covers the second-generation Nest Mini form factor described by Onju. It does not claim support for the first-generation Google Home Mini, other Google Home products, or look-alike revisions. Check the exact model and the board documentation before ordering anything. Photograph cable routing, avoid powered disassembly, and keep the original board and fasteners labeled if rollback matters.

A replacement PCB is a materially different device. Treat microphone privacy, mute behavior, Wi-Fi credentials, firmware updates, and exposed service ports as a new system that you operate—not as security properties inherited from the original product.

Onju v1 vs v2

The original Onju Voice repository is explicitly deprecated and points to Onju v2. Its README describes an experimental conversational platform, an external server, and no full Home Assistant replacement. Use it as history and as evidence for the replacement-board concept, not as the default current software path.

Onju v2 is the current upstream route in this comparison. It separates the ESP32 endpoint from a server pipeline and documents conversational and agentic backends. Earlier v1 demonstrations do not prove every v2 feature, and repository documentation is not KitAgain hands-on validation.

What you actually build for a local LLM

  1. Endpoint: the Onju ESP32-S3 board captures microphone audio and plays returned audio through the reused speaker.
  2. Network: audio moves between the endpoint and a machine you control. Network failure is therefore a voice failure.
  3. ASR: a Whisper-compatible or other documented speech-recognition service turns audio into text.
  4. LLM or agent: an OpenAI-compatible endpoint such as Ollama can run on a suitable LAN host; an optional remote API can be used instead.
  5. TTS: a local or remote speech service produces the reply audio.

Plan for an always-on host that is powerful enough for the models you select. KitAgain has not measured latency, audio quality, power use, or minimum server specifications for this build, so this page gives no performance promise.

When Home Assistant is the better route

If the job is “control my home and use my existing Assist pipeline,” the ESPHome satellite route is usually the clearer mental model. The native ESPHome firmware and the earlier satellite configuration target the Onju PCB, not Google’s original board. They require an installed board and a configured HA voice pipeline.

The board’s shared I2S bus is an important limit: microphone listening and speaker playback cannot operate simultaneously. Wake-word detection pauses during audio playback and resumes afterward. If barge-in or uninterrupted listening is essential, stop before buying parts and compare dedicated hardware.

What you give up, and when to stop

  • Stock services: assume Google Assistant, Cast, and stock multi-room behavior are gone with the original board.
  • Warranty and physical risk: opening the enclosure and replacing electronics can damage cables, plastics, microphones, or the speaker.
  • Appliance simplicity: you now own firmware, Wi-Fi, the voice pipeline, model services, and recovery.
  • Audio concurrency: the ESPHome route documents the shared-I2S listen/playback limitation.
  • Unknown cost: board fabrication, shipping, tools, host hardware, electricity, and optional APIs vary. Use the Onju v2 project record for sourced cost signals; this guide invents no total.

Stop if you cannot confirm the device generation, cannot access the first-flash connector before reassembly, have no safe power/disassembly plan, need stock Cast, or simply want a supported appliance. Home Assistant Voice Preview Edition is the direct buy-not-build comparison; a Wyoming or ESP satellite can also avoid sacrificing the Nest.

FAQ

Can I make a Nest Mini local without Google’s cloud?

Yes, for the second-generation form factor, by replacing the original board with an Onju ESP32-S3 board and running ASR, LLM, and TTS on a home server. It is hardware replacement, not a software unlock of Google firmware.

Does Onju flash the OEM Nest Mini board?

No. The documented Onju route swaps in a custom PCB. Keep the original board if you want a physical rollback option.

Can the ESP32-S3 run the large language model?

Not in this architecture. It is the audio and control endpoint. The model runs on a Mac, PC, server, or optional cloud API.

Should I use Onju v2 or ESPHome?

Choose Onju v2 for its conversational/agent server pipeline. Choose ESPHome when the device should be a Home Assistant Assist satellite. Both require the replacement board.

When should I buy HA Voice PE instead?

Buy rather than retrofit when you want supported hardware, do not want to open and rewire a Nest Mini, need a faster path to HA voice, or cannot accept the documented audio and maintenance trade-offs.
