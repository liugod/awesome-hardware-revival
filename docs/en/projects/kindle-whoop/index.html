What changes for this device

Before

An old Kindle's e-ink display still works, but the original system limits live information display beyond reading.

After

WHOOP data is rendered as an image and displayed on a jailbroken device, with scheduled wake and sleep attempted.

The author's hardware evidence is limited to a Kindle Paperwhite 2, firmware 5.10.3, and one verified wake, connect, update and sleep cycle. The project provides AI-assisted configuration documents for deployment with Codex or Claude. This does not mean AI runs locally on the Kindle or prove that all code was written by AI. One successful cycle cannot establish weeks of battery life.

A good fit for

People with a matching old Kindle, a WHOOP data source and willingness to manage KUAL/linkss and service configuration.

Not a good fit for

People on firmware without confirmed jailbreak support, requiring fully measured long battery life, or unwilling to maintain external data services.

Proposed reproduction checks

  • Verify PW2 and firmware; do not generalize the example to any Kindle.
  • Start with manual refresh, then test scheduled wake and sleep.
  • Record power consumption, failed retries and networking over time, adding multi-day reproduction evidence.

These hardware checks have not been performed by this catalog.

Risks and recovery

Data-loss risk: Possible; Bricking risk: Possible. Route-based guidance, not hardware-tested; these outcomes are not inevitable for every device.

First disable automatic wake/refresh, remove client configuration and revoke API authorization no longer needed. Keep backups of the original device files.
